Lyric Studio

Five treatments for the lyrics panel, running on the same clock and the same timing maths the app ships. Pick one and the differences are a token sheet, not a rewrite — every treatment below sets the same nine custom properties.

What the current panel gets wrong

Six faults, and what causes each

Fixed

Nothing to look at

Every line renders at one flat grey, so the eye has nowhere to land. The panel only distinguishes sung from not sung; with playback stopped, that is a wall of identical text.

Fixed

No sense of depth

A line three above the current one looks exactly like a line twelve below it. Fading and softening by distance from the sung line is what makes a lyric screen feel like it has a focal plane.

Fixed

Lines run the full width

There is no measure cap, so a short chant leaves two-thirds of the panel empty to its right. Capping around 22ch holds the verse together as a block.

Fixed

The stray ♪

An untimed empty line rendered as a lone music note at the top, which reads as a glitch rather than a rest. It is three filling dots now — see withInterludes in src/lib/lyrics.ts.

Fixed

No ground

A flat charcoal rectangle. The track's own colours already exist — fallbackCover derives them and trackVisuals already paints them behind the full-screen player — but the lyrics panel never asks for them.

Fixed

One rhythm for everything

Uniform spacing and a single weight. The sung line should get measurably more room than the rest; right now it gets the same 1.4 rem as a line nobody is reading.

The hardest part

What to do with the space to the right

A lyric line is short and a panel is any width the user drags it to. Text cannot fill that space, and stretching it across the full width would be worse — a 90-character line is unreadable at display size. Every player that solves this well solves it the same three ways at once.

Shipped

1 · Grow the type with the panel

Not with the window — with the container. Three fixed steps mean every width between two of them strands the column in the middle of an empty panel. clamp(1.75rem, 1rem + 2.6cqi, 3rem) scales continuously, so a wider panel spends its width on bigger words before it spends any on empty space.

Shipped

2 · Cap the measure

About 22 characters, in ch so it grows with the type. This is what stops the line running the full width — but on its own it only moves the empty space, which is the gap in the report.

Shipped

3 · Centre the block, not the text

The half that was missing. width: min(100%, 22ch); margin-inline: auto on the column, with the lines still left-aligned inside it. One clean left edge to read down, and the leftover width split evenly so it reads as margin instead of as something absent.

Shipped

4 · Give the ground something to be

Margin still has to look intentional. The artwork wash fills it with the track's own colours, so the width beside the column reads as atmosphere rather than as a panel that failed to fill itself.

A fifth answer exists and is not shipped: at very wide widths Apple Music stops giving lyrics the whole panel and puts the artwork beside them instead. That is a layout change to the full-screen player rather than to the lyrics panel, and it is the right next move if the column still feels lonely past about 1400 px.
